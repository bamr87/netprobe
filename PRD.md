# Product Requirements Document (PRD): netprobe

> A Go network diagnostics toolkit with a terminal UI: ping, port scan, DNS, traceroute and HTTP probes.

Open work is tracked in [GitHub Issues](https://github.com/bamr87/netprobe/issues) and as `status: planned` entries in [features/features.yml](features/features.yml).

## 1. Overview

One binary for the network questions you ask every week, with a live TUI dashboard built on Bubble Tea.

| Version | Date | Notes |
| --- | --- | --- |
| 0.1 | 2026-10-28 | Initial requirements and phased roadmap (repo foundation). |

## 2. Goals

- Fast concurrent TCP port scanner and ICMP/TCP ping
- DNS lookup and traceroute views
- Bubble Tea TUI tying probes into one dashboard

Non-goals (near term): production hosting, paid services, anything outside the roadmap below without a PRD change.

## 3. Users

- The maintainer, learning go concurrency (goroutines, contexts), raw sockets and network protocols by building.
- Fleet agents (hub evolution loop, backlog fan-out, `evolve` lane) that grow the repo one reviewed PR at a time.
- Fleet tie-in: Diagnoses fleet hosts and services (fleet-infra cluster, fleet-observe endpoints) and can feed probe results to the activity log.

## 4. Requirements

Phases are the build order: an agent picks the earliest unserved requirement first.

### 4.1 Phase 1 — Foundation

- FR1: TCP connect probe for host:port with timeout, exposed as a CLI subcommand
- FR2: Concurrent port range scan with rate limiting

### 4.2 Phase 2 — Core

- FR3: DNS lookup subcommand (A/AAAA/MX/TXT)
- FR4: Traceroute view

### 4.3 Phase 3 — Fleet integration

- FR5: Bubble Tea TUI dashboard combining probes
- FR6: JSON output for scripting

### 4.4 Non-functional

- NFR1: CI (`.github/workflows/ci.yml`, the fleet standard gate) passes on every PR.
- NFR2: No secrets or credentials are committed; configuration comes from environment variables.
- NFR3: Autonomous lanes are off by default, open pull requests only, and never merge.
